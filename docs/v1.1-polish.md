# v1.1 Polish Features

Four scoped improvements deferred from v1 because the audit confirmed each
was an acceptable trade-off at launch. Each is a self-contained ticket —
no dependencies between them — so they can ship in any order or not at all.

---

## 1. Argon2id password hashing

**Problem:** `hashPassword = SHA-256(password + slug)` is too fast. A leaked
Redis dump lets an attacker try billions of guesses per second on a GPU.
Slug-as-salt is public knowledge, so the hash is effectively unsalted.

**Fix:** Replace SHA-256 with Argon2id (memory-hard, GPU-resistant).
Generate a 16-byte random salt per link, store it alongside the hash as
`argon2id$v=19$m=65536,t=3,p=4$<salt>$<hash>`.

**Cost:** ~30 min implementation + new dep (`@node-rs/argon2` or
`hash-wasm`). One test to verify round-trip + reject bad password. No
schema migration needed — `passwordHash` field already exists; new format
is forward-compatible.

**Risk:** Low. Old SHA-256 hashes won't verify with new code, so any
existing password-protected links stop working. Acceptable for v1.1
(v1 had near-zero adoption).

**Verifies:** VibeSec audit finding on `src/lib/hash.ts:hashPassword`.

## 2. CSP with Next.js nonce

**Problem:** No Content-Security-Policy header. Today, every dynamic field
rendered as a React text node is XSS-safe — but there's no defence in depth.
A future bug introducing `dangerouslySetInnerHTML`, or a typo in a slug
regex that admits HTML metacharacters, opens XSS.

**Fix:** Emit a per-request nonce via Next.js's `headers()` middleware
mechanism, set `script-src 'self' 'nonce-{nonce}' 'strict-dynamic'`, and
have Next.js inject the nonce into its inline scripts. Tightens the
current "no inline scripts of our own" posture into an enforced rule.

**Cost:** ~1 hour. Adds a `proxy.ts` middleware that generates the nonce
and adds the CSP header. Verify build still emits `__NEXT_DATA__` inline
scripts with the nonce.

**Risk:** Medium. CSP can break third-party integrations (we don't have
any, but sonner/sonner-toast inlines styles). May need
`style-src 'self' 'unsafe-inline'` relaxation. Will require build-time
verification.

**Verifies:** VibeSec audit finding on `next.config.ts` (no CSP).

## 3. Reverse-lookup index for edit tokens

**Problem:** `findSlugByToken` does a linear scan over every link in the
`links:index` sorted set, calling `HGETALL` on each. At ~10K links this is
the dominant cost on every `/edit/{token}` page load.

**Fix:** Maintain a reverse-lookup hash: `token:{tokenHash} = slug`. Add
it to `createLink`, remove from `deleteLink`. `findSlugByToken` becomes
one `HGET`.

**Cost:** ~30 min. Adds one write per create, one del per delete. One new
test. Storage cost negligible (one extra key per link, ~32 bytes).

**Risk:** Low. The hash never changes for a given link — no update path
needed (edit tokens rotate on... actually, we don't have token rotation
yet, so this stays simple).

**Verifies:** VibeSec audit finding on `src/lib/links.ts:findSlugByToken`.

## 4. DNS-resolving URL validation

**Problem:** `isPrivateOrLoopbackHost` is host-string-only. An attacker
can submit `https://2130706433` (decimal for 127.0.0.1), `https://0x7f.0x0.0x0.0x1`
(hex), or use a domain whose DNS resolves to a private IP (DNS rebinding).
The URL string looks valid, but the actual request would land on
loopback/internal.

**Fix:** After string-level checks, resolve the hostname via `dns.lookup()`
and re-run the private-range check on the resolved IP. Reject any IDN
(`*.xn--*`) domain. Pin the resolved IP for the actual request if we ever
make server-side fetches (we don't today, so this is just defence in
depth).

**Cost:** ~1 hour. `dns.lookup` is in Node stdlib. New test for the
decimal/hex/IPv6-mapped cases. Add IDN reject.

**Risk:** Low. Resolving adds ~5 ms to `validateUrl`. No external
dependencies.

**Verifies:** VibeSec audit finding on `src/lib/url.ts`.

## Summary

| # | Fix | Effort | Risk | Defends against |
|---|---|---|---|---|
| 1 | Argon2id | 30 min | Low | Offline cracking if Redis leaks |
| 2 | CSP + nonce | 1 hour | Medium | XSS via future code bug |
| 3 | Token reverse index | 30 min | Low | Slow `/edit/{token}` at scale |
| 4 | DNS-resolving validate | 1 hour | Low | SSRF/DNS-rebinding via URL field |

**Total:** ~3 hours work, all independent, all small.
